## 编码模式说明

程序提供 **CRF** 和 **2-Pass VBR** 两种编码模式，默认推荐 CRF。osu! 背景视频通常是动漫 OP，这类画面往往包含清晰的边缘和大面积纯色区域，较容易压缩。使用 CRF 单遍编码，通常可以在画质、文件大小和编码速度之间取得较好的平衡。需要更可预测地控制文件大小时，可使用 2-Pass VBR。

### CRF 模式（Constant Rate Factor）

**工作原理：** 根据 CRF 值控制编码质量，实际码率随画面复杂度变化。

| 项目 | 说明 |
|------|------|
| 控制方式 | 设置 CRF 值，范围为 1–51 |
| 默认值 | 26 |
| 数值含义 | CRF 值越小，画质通常越好，文件也越大；CRF 值越大，画质通常越低，文件也越小 |
| 输出大小 | 无法仅凭 CRF 值准确预测，实际大小取决于视频内容 |
| 编码速度 | 单遍编码，通常快于 2-Pass VBR |
| 适用场景 | 大多数 osu! 背景视频，尤其是需要快速得到较小文件的动漫 OP |

**CRF 值参考：**

| CRF 值 | 画质参考 | 说明 |
|--------|----------|------|
| 18–23 | 较高 | 画质通常较好，文件可能较大 |
| 23–26 | 中高 | 可作为一般用途的参考范围 |
| 26–28 | 中等 | 可作为 osu! 背景视频的试编码起点 |
| 28–32 | 较低 | 文件通常更小，但画面损失更明显 |
| 32 及以上 | 较低 | 通常不建议用于 osu! 背景视频 |

**优点：**

- 只需设置 CRF 值，无需预先估算目标码率。
- 动漫 OP 中常见的清晰边缘和大面积纯色区域通常较易压缩，CRF 26–28 可作为兼顾画质与文件大小的起始范围；实际效果仍取决于视频内容。

**局限：**

- 输出文件大小无法直接指定。若需要满足特定体积限制，可能需要多次编码并调整 CRF 值。
- 复杂画面或噪点较多的片段可能产生较大的输出文件，超出目标体积。

### 2-Pass VBR 模式（两遍可变码率编码）

**工作原理：** 第一遍分析视频内容，第二遍根据分析结果分配比特，以达到设定的目标码率。

| 项目 | 说明 |
|------|------|
| 控制方式 | 设置目标视频码率，单位为 kbps |
| 默认值 | 码率输入框留空，或输入的数值不是正数时，程序使用 800 kbps |
| 输出大小 | 比 CRF 模式更容易预测和控制；实际文件大小还会受到音频数据和封装开销等因素影响 |
| 编码速度 | 需要执行两遍编码，整体耗时通常更长 |
| 适用场景 | 需要按目标体积规划文件大小，或不希望反复调整 CRF 值的场景 |

**优点：**

- 可根据视频时长和目标体积估算所需码率，减少反复试编码的次数。
- 编码器可根据第一遍的分析结果，在复杂场景中分配更多比特，在简单场景中减少比特。

**局限：**

- 需要执行两遍编码，耗时通常高于单遍 CRF 编码。
- 需要根据视频时长和目标文件大小选择合适的码率；码率设置不当时，最终体积可能偏离目标。

**文件大小估算示例：** 以下按视频码率为 800 kbps 粗略估算，未计入音频数据和封装开销，因此实际输出文件可能更大。

| 视频时长 | 视频数据预估大小 |
|----------|------------------|
| 1 分钟 | 约 6 MB |
| 1.5 分钟 | 约 9 MB |
| 2 分钟 | 约 12 MB |
| 2.5 分钟 | 约 15 MB |
| 3 分钟 | 约 18 MB |

## osu! 背景视频推荐配置

对于常见的 osu! 背景视频，例如时长在 2 分钟以内的动漫 OP，如果目标文件大小约为 15 MB 或更小，可从以下配置开始尝试：

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| 编码模式 | **CRF**（默认） | 适合快速试编码；可通过调整 CRF 值改变输出大小 |
| CRF | **26–28** | 建议先使用 26 编码，再根据输出大小调整 |
| 分辨率 | **720p，或符合限制的原分辨率** | 保持原视频宽高比；osu! 要求输出尺寸不超过 1280 × 720 |
| FPS | **24** | 程序固定输出为 24 fps，界面中没有可调整此参数的选项 |

**建议流程：** 先使用 CRF 26 编码。若输出文件过大，将 CRF 值提高 1–2 后重新编码；若文件大小有余量且需要更高画质，则将 CRF 值降低 1–2。根据素材复杂度，可能需要重复调整。

如果文件大小必须更贴近指定目标，例如谱面存在严格的体积限制，可改用 **2-Pass VBR**，根据视频时长估算目标码率。两遍编码的耗时通常更长，但输出大小更容易预测。

**2-Pass VBR 码率参考：**

- 视频时长不超过 1 分钟：`800–1000 kbps`
- 视频时长为 1–1.5 分钟：`700–900 kbps`
- 视频时长为 1.5–2 分钟：`600–800 kbps`

以上范围仅供初始估算。实际所需码率会随画面复杂度、音频数据和目标文件大小变化。

## 技术参数说明

### 默认编码参数

程序使用以下固定编码参数：

| 参数 | 值 | 说明 |
|------|----|------|
| 编码器 | `libx264` | 用于生成 H.264 视频的编码器 |
| 编码预设 | `veryslow` | 编码耗时较长，通常更注重压缩效率 |
| 编码配置文件 | `high` | H.264 High Profile |
| 编码级别 | `5.2` | H.264 Level 5.2 |
| 像素格式 | `yuv420p` | 兼容性较广的像素格式 |
| GOP 大小 | `300` | 最大关键帧间隔参数 |
| 最小 GOP | `240` | 最小关键帧间隔参数 |
| B 帧数量 | `16` | 设置 B 帧数量上限 |
| 运动估计算法 | `UMH` | 使用 UMH 运动估计算法 |
| 子像素细分等级 | `11` | 设置子像素运动估计的细分等级 |

### 高级 x264 参数

程序使用以下 x264 参数字符串：

```text
scenecut=0:ref=16:bframes=16:b-adapt=2:direct=auto:me=umh:subme=11:trellis=2:rc-lookahead=60:aq-mode=3:aq-strength=1.0:psy-rd=1.0,0.15:deblock=-1,-1:weightp=2:cabac=1:merange=32
```

该字符串通过 FFmpeg 的 `-x264-params` 选项传入，定义在 `src/services/args.rs` 文件中的 `X264_PARAMS` 常量中。参数之间使用冒号分隔；参数值中的逗号（例如 `psy-rd=1.0,0.15` 和 `deblock=-1,-1`）属于参数值本身，不是参数分隔符。
